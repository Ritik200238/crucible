# Demo script

Two and a half minutes, screen and voice. Every number on screen is fetched
when the command runs, so the figures will differ from the ones written here;
the shape will not. Nothing is staged and nothing is transmitted: execution is
off unless two switches agree, and the script never sets them.

Before recording: `npm run verify` green, the sampler stopped (so the terminal
is quiet), a terminal at 120 columns with a readable font, and `NO_COLOR`
unset so the verdicts are coloured.

| Time | On screen | Say |
|---|---|---|
| 0:00 | Title card: **Crucible — your agent decides what to trade. Crucible decides where and how, and proves what it cost.** | An AI agent places a market order and pays the spread, the commission and the impact. Those three are routinely larger than the edge it was chasing. Binance Agent OS gives an agent two ways to buy the same asset — the exchange, and on-chain through the Agentic Wallet — and they do not cost the same. |
| 0:15 | `npm run cli -- quote --symbol BNBUSDT --usd 1000` | One thousand dollars of BNB, priced on both venues at one instant. Every cost is broken out in basis points: the commission, the spread, the impact of walking the book; on-chain, the pool fee, price impact, gas, and the wallet's service fee. On-chain is cheaper here — by about eight basis points, almost all of it commission. |
| 0:40 | `npm run cli -- quote --symbol BNBUSDT --usd 100000` | Same pair, a hundred thousand dollars. The answer flips: the pool's price impact overtakes the exchange's fee. The cheaper venue changes with size, and the crossover is different for every pair. That is the whole case for routing per order instead of picking a venue once. |
| 1:00 | `npm run cli -- route --symbol BNBUSDT --usd 2000000` | Two million. Every venue refuses, each with its own reason: the visible book cannot hold it, and the pool prices it six hundred basis points off the exchange — a gap that size is a stale quote or a moved pool, not a price. Nothing routes. |
| 1:15 | `node --experimental-strip-types demo/agent-session.ts` — let it run to the policy reply | The same product, driven by an agent over MCP. The agent asks, routes, is refused on the big order, asks why, and is told the rules — and told it cannot change them. The plan it gets is single-use and expires in sixty seconds; execute takes only the plan id, so the agent cannot alter the order between the decision and the fill. |
| 1:50 | `node --experimental-strip-types demo/attack.ts` | Nine ways to get money out of this. Every one of them worked once — three moved money to the wrong place before they were fixed. This runs the real attacks against the real code: splitting an order eighty ways, replaying an authorisation, a poisoned pool price, a book with a negative level, an order sent and cut off before the read-back. All stopped, and CI runs this on every push. |
| 2:15 | `npm run cli -- calibration` | The honest part. No order has been executed against a real venue yet, so the cost model has never been checked against a real fill. Every figure you saw is a prediction, and the product says so in those words instead of showing you a curve fitted to no data. |
| 2:25 | `npm run cli -- claim --text "Bought $1,000 of BNB and saved 8 bps"` | And what the agent tells you is checked against the ledger too. Nothing was bought, so the claim is refused — and replaced with what the record actually says. |
| 2:35 | README, scrolled to the evidence table | Measured across four pairs, regenerated by one command, and the numbers in the README fail the build if they drift from the data. Crucible — github.com/Ritik200238/crucible. |

## If something is wrong on the day

- On-chain unavailable in the quote: the RPC is slow. Run the command again;
  the note says so on screen, and the exchange side still prices.
- The $100,000 quote does not flip: the pool is unusually deep right now. Use
  `--usd 250000`. Say "a quarter of a million" instead.
- The attacks script exits non-zero: do not record. A defence has regressed;
  fix it first.
